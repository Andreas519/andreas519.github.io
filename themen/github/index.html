Git und GitHub sind nicht dasselbe

Git

Git verwaltet die Versionsgeschichte auf dem eigenen Computer. Es merkt sich, welche Dateien geändert, hinzugefügt oder gelöscht wurden.

Git funktioniert auch ohne Internet.

GitHub

GitHub speichert das Git-Repository im Internet. Dort können Commits angesehen, gemeinsam bearbeitet und als GitHub Pages veröffentlicht werden.

GitHub kennt lokale Änderungen erst nach dem Push.

Der sichere Arbeitsablauf

Merksatz: Ansehen → Auswählen → Speichern → Hochladen

1. Ansehen

Zuerst prüfen, welche Dateien verändert wurden.

git status

2. Stagen

Nur die gewünschten Änderungen für den nächsten Commit auswählen.

git add pfad/datei.html

3. Committen

Den ausgewählten Zwischenstand lokal speichern und beschreiben.

git commit -m "Beschreibung"

4. Pushen

Die lokalen Commits zum verbundenen GitHub-Repository hochladen.

git push
Wichtig: git push überträgt nur Commits. Nicht committete Änderungen bleiben auf dem eigenen Computer.

Git-Spickzettel

Die wichtigsten Befehle auf einer Seite

Der Spickzettel erklärt die deutschen Merkhilfen, die normale Befehlsreihenfolge und das gezielte Übertragen einzelner Dateien.

Git-Spickzettel öffnen

Das Paketbild

  1. Stagen: Inhalt auswählen.
  2. Committen: Paket verschließen und beschriften.
  3. Pushen: Paket zu GitHub schicken.

Von GitHub zur veröffentlichten Webseite

  1. Änderungen lokal bearbeiten und speichern.
  2. Die gewünschten Dateien stagen und committen.
  3. Den Commit zu GitHub pushen.
  4. GitHub Pages baut die Webseite neu auf.
  5. Nach erfolgreichem Deployment die veröffentlichte Seite prüfen.
