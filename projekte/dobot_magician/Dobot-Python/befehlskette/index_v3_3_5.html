Neue Verfahrensweise für die weitere Projektentwicklung - OpenAI Codex

Codex wird nun die Softwareentwicklung vollständig übernehmen.
Codex hat das Projekt in eine eigene Arbeitsumgebung entpackt
Codex kann die einzelene Programmdateien analysieren und auch Testläufe durchführen.
Lediglich das Aufspielen der Software auf dem ESP32 und das praktische Zusammenspiel aller Komponenten mit dem Dobot muss ich selbst organisieren.

  • Ich und auch Codex können die Programme testen.
  • Ich werde keine Änderungen an den Programmen vornehmen, ich informiere Codex über feststellte Fehler.
  • Ich formuliere meine Änderungswünsche.
  • Codex übernimmt die Entwicklung, teilweise das Testen und auch das Dokumentieren.
  • Jede Änderung an einer Softwarekomponente wird von Codex mit einer internen Versionsnummer versehen.
  • Wir wiederholen diesen Prozess, bis die Software den Anforderungen entspricht.

Der Vorteil dieser Vorgehensweise ist, dass ich mich auf die praktische Arbeit mit dem Dobot und seinem Umfeld konzentrieren kann und Codex die Softwareentwicklung übernimmt.
Ich plaziere Sensoren und Aktoren, die ich für die Arbeit mit dem Dobot plane.
Ich teste mit kleinen Testprogrammen, die ich von Codex anfordere, die hinzugefügten Komponenten
Codex bindet dies in das Gesamtprojekt ein und entwickelt die Software, die diese Komponenten steuert.

Der gesamte Entwicklungsprozess wird so organisiert, dass ich mich auf die praktische Arbeit konzentrieren kann, während Codex die Softwareentwicklung übernimmt und alle Versionen sichert.
